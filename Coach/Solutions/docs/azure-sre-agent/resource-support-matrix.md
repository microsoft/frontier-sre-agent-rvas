# Azure SRE Agent Resource Support Matrix

This matrix defines the source of truth for each resource surface. It prevents accidental drift between Terraform-managed infrastructure and API-managed agent configuration. Manifests whose names start with `example-` are reference templates only and are excluded from every deployment path; deploy them explicitly with `--file` if needed.

| Incident filters | `06-sre-agent-configuration/automations/incident-filters` | Data-plane `/api/v2/extendedAgent/incidentFilters/{name}` | Requires matching active incident platform first, for example `AzMonitor` before AzMonitor filters. The platform PATCH is asynchronous, so the first filter PUT can return HTTP 400; `sre-agent-config.sh` retries automatically (`SRE_AGENT_INCIDENT_FILTER_MAX_ATTEMPTS`, default 5). Routing supports severity (`priorities`, Sev0-Sev4) and title matching (`titleContains`, `titleContainsAny`, `titleContainsAll`, `titleNotContains`; case-insensitive). This repo applies a **domain-routing rule** (2026-06-14): five plans, each owning a failure domain keyed by incident title across severities, disjoint by construction — Sev1 `food`→`aca-app-incident-handler` (ACA) and `afw`→`network-traffic-analyst` (hub firewall); Sev2 `nginx`→`iaas-vm-incident-handler` (web tier) and not-`nginx`→`network-traffic-analyst` (hub networking); Sev3→`azure-resource-config-auditor`. Start narrow to control cost and blast radius. | https://learn.microsoft.com/en-us/azure/sre-agent/pricing-billing and https://github.com/microsoft/sre-agent/pull/200 |
| Common prompts | `06-sre-agent-configuration/common-prompts` | Data-plane `/api/v2/extendedAgent/commonprompts/{name}` | Long prompt text should live in Markdown. | https://learn.microsoft.com/en-us/azure/sre-agent/api-reference |
| Repositories | `06-sre-agent-configuration/repos` | Data-plane REST API | Requires authentication setup. Do not commit PATs. Set `spec.authConnectorName` to link a repo to an OAuth connector (for example the `github` connector). | https://learn.microsoft.com/en-us/azure/sre-agent/api-reference |
| Knowledge files | `06-sre-agent-configuration/knowledge/files` | Data-plane multipart upload | Max limits are defined by the API reference. Avoid secrets and personal data. `find_knowledge_files` recurses subdirectories, so group documents under `knowledge/files/<group>/` (for example `sample-food/`, `vnet-flow-logs/`); the upload keys by file basename, which must stay unique across groups. | https://learn.microsoft.com/en-us/azure/sre-agent/api-reference |
| Hooks | `06-sre-agent-configuration/hooks` | Data-plane REST API | Use for production governance and approval boundaries. This demo lab currently deploys **no hook** (maximum-autonomy decision, 2026-06-14): `block-unsafe-remediation` was deleted live and its manifest renamed `example-*`. The API ignores `spec.enabled`; disable a hook by not deploying it. | https://learn.microsoft.com/en-us/azure/sre-agent/deploy-iac |
| Plugin configurations | `06-sre-agent-configuration/plugin-configs`, `06-sre-agent-configuration/plugins/marketplaces`, `06-sre-agent-configuration/plugins/installations` | Data-plane REST API | Keep plugin secrets outside Git. Marketplaces/installations are POST surfaces; the script has no per-object DELETE for them, but live validation on 2026-06-12 showed the data-plane DELETE endpoints do respond (HTTP 202), so examples can be purged with a direct REST call when required. | https://learn.microsoft.com/en-us/azure/sre-agent/api-reference |

The script has no delete path, but `DELETE /api/v1/httptriggers/{id}` works (HTTP 200, verified 2026-06-12) for purging examples. Add only after a security review. | https://learn.microsoft.com/en-us/azure/sre-agent/api-reference |

## Decision Rule

Use this order of preference:

1. AzureRM when the provider supports the resource.
2. AzAPI when Microsoft Learn documents the resource type for Terraform.
3. Azure SRE Agent data-plane REST APIs for Agent Extensions and other agent-specific configuration not safely supported by ARM in external tenants.

Do not move API-only resources into Terraform with generic external commands. That would hide drift and mix two state models.
