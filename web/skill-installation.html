Azure SRE Agent scenario skills

Use a scenario skill

Choose only the skills you need. Each scenario can map to one or more reusable skills. Viewing, copying or downloading a skill does not install it, grant permissions or run it.

1. Download and inspect

  1. Find a skill in the Skills catalog or open its mapped scenario in Scenario Explorer. Inspect it with View instructions.
  2. Select Download complete bundle and extract the ZIP locally. It contains skills/<skill-id>/SKILL.md, supporting references/ and tools/, a repository configuration manifest, and license notices.
  3. Read the evidence workflow, permissions, output contract and limitations. Examples are synthetic, not customer evidence or approved thresholds.

Copy instructions copies SKILL.md only. Supporting references and Python tools are still required. A ZIP is a distribution package, not a documented native Azure SRE Agent import format.

2. Prepare the approved environment

  • Confirm the tenant, explicit subscription and resource allowlist, intended identity and UTC observation window.
  • Review the skill's explicit tool list and configure only approved tools and permissions in the host. Terminal access must be constrained to validated read commands and local analysis. Instructions alone do not enforce authorization.
  • Review references/governance.json. Its defaults deny unapproved scope. The host must enforce policy checks, approval requirements, rate limits and append only audit logging.
  • Do not attach an upload tool unless customer delivery is separately approved. Resource changes, deployment, scheduling, uploads and messages need separate approval.

3. Install the complete skill

Portal: Microsoft Learn documents skill creation in Builder > Skills. Create the skill using its name, description and SKILL.md, add supporting files while preserving the relative references/, tools/ and any nested shared/ paths, and attach the approved runtime tools. Check the current portal for available attachment controls. Do not upload only SKILL.md and assume its linked dependencies are present.

Repository automation: the bundle's skill.yaml follows this workshop's manifest conventions. Use the existing configuration script from a checkout of this repository in Linux Bash. Review a local validation and plan, then apply only after approval. See the library setup and command examples. This library is not added to the workshop's default agent deployment.

Assessment bundles preserve their supplied checks and report layouts. Some collectors need host packages such as requests and azure-identity; the architecture generator also needs pandas and an Excel engine. Keep the nested shared runtime intact. Optional agent and IaC examples are not automatically deployed. Review each skill's prerequisites before execution.

4. Test a small investigation

Start with approved scope and known evidence. Check a healthy case, a finding, and denied or missing evidence. A missing observation must remain visible, not become a healthy result. Six Management skills include a local analyzer and synthetic evidence fixtures. Run its commands from the extracted skill directory and supply normalized input with customer approved criteria.

Record a customer environment smoke test separately. Local packaging tests do not establish live Azure validation, service access or operational readiness. Review and sanitize results before any customer delivery.
